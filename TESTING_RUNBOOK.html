FOLLISAVE — Bench Runbook

first‑time · end‑to‑end
Operations guide

Run the whole system, end to end

A follow‑every‑line guide to bring up the operator web app (PC), the ESP32 pouch (USB), and the patient console (phone, over Bluetooth) — and to watch them mirror each other. Written for a first run, with a full fix‑it FAQ.

  ESP32 pouch  ──USB (COM port)──►  PC ──► Backend :8000 ──► Web app :5173   ← you drive here
       ▲
       └───────────── Bluetooth LE ─────────────►  Android phone · Console app   ← patient drives here

  Phone ──USB──► PC   only to build / reload the app. Control is always over Bluetooth.

The PC talks to the pouch over the USB serial cable; the phone talks to it over Bluetooth. They run at the same time — that is the point: whoever starts or stops a session, both screens follow.

Keep three terminal windows open on the PC the whole time. Don't close them.

Terminal 1

Backend

FastAPI on port 8000 — talks to the pouch over serial.

Terminal 2

Frontend

The operator web app on port 5173.

Terminal 3

Metro

The phone app's bundler — keep it alive while testing.

01 Get the code

Open PowerShell where you keep projects. First time:

PowerShell
> git clone https://github.com/MarkIOP-med/FOLLI_POUCH.git
> cd FOLLI_POUCH

Already have the folder? Just update it:

PowerShell
> cd FOLLI_POUCH
> git checkout main
> git pull

The firmware on the ESP32 is already the latest — flashed before the rig was handed over, so you don't need to flash anything. (If you ever do, see Appendix A.)

02 Connect & power the pouch

Do this before starting the backend.

  1. Plug the ESP32 into the PC by USB. This powers the board's logic and creates the COM port. Note the number — Device Manager → Ports (COM & LPT) → "Silicon Labs CP210x… (COMx)". You'll need COMx.
  2. Turn on the bench actuator power supply (the one driving the pump, valves and relief). The ESP alone can't inflate anything.
  3. Flip the pump's manual ON switch. Forget this and nothing inflates — it's the single most common "it doesn't work".
  4. Put a balloon on TEMPLE and EAR. Only those two inflate on this bench — FRONT and BACK valves are physically dead (known hardware limit).
Serial reset caveat

Every time the PC opens the COM port, the ESP32 reboots and takes about 6 seconds before it answers. Normal — just wait after you press Connect.

03 Start the backend — Terminal 1

Terminal 1 · backend
> cd FOLLI_POUCH\POUCH_APP\backend
> python -m venv .venv
> .\.venv\Scripts\Activate.ps1
> pip install -r requirements.txt
> python -m uvicorn app.main:app --port 8000

Leave it running. On first run it creates a fresh database and seeds a "Mock Pouch" so the app works even with no hardware.

Verify

Open http://127.0.0.1:8000/api/health — you should see {"ok":true}.

The database starts empty of patients and knows only the Mock Pouch. Steps 05–06 add your real pouch and a patient.

04 Start the web app — Terminal 2

Terminal 2 · frontend
> cd FOLLI_POUCH\POUCH_APP\frontend
> npm install
> npm run dev

Open http://localhost:5173 — this is the operator app. It reaches the backend automatically (so the backend must be up first). You'll land on Home with a Mock Pouch card.

05 Register & connect your pouch

  1. Open Admin (the gear / admin area).
  2. In Devices → Add device, fill in:
    • ID — anything short, e.g. POUCH1
    • Label — e.g. Bench pouch
    • Transport — serial
    • Port — pick your COMx (the CP2102 port is starred ★)
  3. Back on Home, your pouch card appears. Click ENTER. It connects over serial (give it the ~6 s reset), then opens Diagnostics.
Verify

Status shows Connected and the telemetry rate is a live number (a few Hz), not 0. Pressures read ~0 while idle.

06 Create a patient (balloon‑safe)

The patient console only runs a clinician‑assigned patient, so create one.

  1. Open Users (patients) → Create patient.
  2. Fill in:
    • Full name — e.g. Bench Test
    • National ID — leave blank. (If typed, it must be a valid Israeli ID or it's rejected; blank avoids that.)
    • Regime — use only the working zones. The ceiling is 130 mmHg, so you can prescribe up to 125 directly — e.g. TEMPLE 90, EAR 125, or gentler TEMPLE 40, EAR 40. Keep FRONT 0, BACK 0.
    • Optionally set a massage level (1–3) per zone.
The 130 ceiling is a bench value

The ceiling ships at 130 mmHg so a full 125 regime works with nothing to change — that's why you don't touch any setting. It also lets the patient console dial a zone high. Before anything is ever worn on a person's head, lower the ceiling to 70 in Admin → Settings → Max pressure.

07 Put the console app on the phone — Terminal 3

7a · Prepare the phone (once)

  1. Settings → About phone → tap Build number seven times to unlock Developer options.
  2. Developer options → turn on USB debugging.
  3. Turn on Bluetooth. Keep the phone unlocked while building.
  4. Plug the phone into the PC by USB. Run adb devices — it should list as device. If it says unauthorized, tap Allow on the phone's "Allow USB debugging?" pop‑up (tick "always allow from this computer").

7b · Build & install

Terminal 3 · console
> cd FOLLI_POUCH\FOLLI_CONSOLE
> npm install
> npm run android   # syncs assets, builds, installs, launches
  • First build takes ~5–15 minutes; later ones are fast.
  • It also starts Metro in this terminal — leave it running. Close it and the app shows a red error screen.
  • When Android asks for Bluetooth / "Nearby devices" permission, tap Allow — the app can't scan without it.

Two harmless red boxes may flash on first launch (ExpoNavigationBar, ExpoKeepAwake — kiosk niceties the dev build can't do). Dismiss them; they don't affect anything.

7c · Confirm the Bluetooth link — look at the console app's top status bar:

  • "Connected" (green) = joined the pouch over Bluetooth. ✅
  • "Disconnected" (red) = not yet. The app retries every few seconds on its own — give it ~10 s. Still red? See the FAQ.

You should also see the patient's name — selecting/creating the patient checked them out to the pouch, and the console mirrors that.

08 The end‑to‑end tests

Keep the web app (Diagnostics for your pouch) and the phone side by side.

Test A — Operator starts, phone mirrors

  1. On the web app, make sure your patient is selected (the console should already show their name).
  2. Press START on the web app.
  3. Watch: the pump runs; TEMPLE and EAR balloons inflate to their prescribed pressures and hold.
  4. On the phone, untouched: it flips to ACTIVE with a running clock, a STOP button, and live pressures — same session, same clock.
Pass

Balloons hold ~40; both screens show ACTIVE with the same clock and targets; the patient name shows on both.

Test B — Phone starts, operator adopts

  1. STOP first if a session is running (web STOP, or hold the phone's STOP ~1.5 s). Wait for the balloons to empty.
  2. On the phone, press START.
  3. Watch: balloons inflate; the web app raises a session on its own — the device clock, the real targets, and a "started from the patient console" note.
Pass

The web app shows the running session it did not start, with the correct clock and targets (not zeros) and the patient's name.

Test C — Trim, massage & cross‑stop

  • Trim a zone: change one zone's pressure a little and press SET (phone or web). Only that zone's target changes — on both screens.
  • Massage: tap a zone's level and its SET / ▶ — the motor runs one burst (~20 s) and stops itself; other zones keep running.
  • Cross‑stop: START on the web, then hold STOP on the phone. Balloons vent and the web app shows "stopped from the patient console."
Pass

Every change on one side appears on the other within a second or two; STOP always empties the balloons.

Venting takes a moment

STOP uses a pulsed vent (burst → settle → measure) and can take up to ~15 s to fully empty a stiff balloon. Let it finish before starting again — don't stack a new START on a half‑full load.

09 Shut down cleanly

  1. STOP any running session and let the balloons empty.
  2. Close the phone app; Ctrl‑C the Metro terminal.
  3. In the web app, Disconnect the pouch (or just close the tab).
  4. Ctrl‑C the Frontend terminal, then the Backend terminal.
  5. Pump switch off, bench power off, unplug USB.

10 FAQ · fixes you can apply mid‑test

The pouch doesn't appear as a COM port

Install the Silicon Labs CP210x driver, re‑plug the board, and re‑check Device Manager → Ports (COM & LPT).

Backend won't open the port — "Access is denied" / "could not open COMx"

Something else holds the port. Close the Arduino Serial Monitor, any second backend window, or an arduino-cli upload — only one program can own a COM port. Then press Connect again. Remember the ~6 s reset after connect: the rate is 0 for a few seconds, which is normal.

I pressed START but nothing inflates

Almost always the pump's manual switch is off, or the bench power supply is off. Check both. Also confirm the balloons are on TEMPLE / EAR — FRONT and BACK are dead on this bench.

Only two balloons ever inflate

Correct — valves 0 (FRONT) and 3 (BACK) are physically dead. Test on TEMPLE and EAR only.

Web app can't reach the backend / pressures never load

The backend must be running first. Check /api/health returns {"ok":true}. If not, read Terminal 1 for the error. The web app proxies /api to port 8000 — don't change the port.

Console shows "Disconnected" and won't connect

In order: (1) is the pouch powered (USB in, LED on)? (2) is the phone's Bluetooth on and the app's Nearby‑devices permission granted? (3) walk the phone closer. (4) Power‑cycle the pouch (unplug/replug USB, wait ~10 s) — the app auto‑reconnects. It already retries every ~4 s, so you rarely need to restart it.

Build log: "Timed out scanning for FOLLI pouch"

The phone can't see the board advertising — same checklist as above. Also make sure no other device grabbed the pouch's one Bluetooth slot (a second phone, or a BLE scanner app). Only one Bluetooth central can connect at a time — the PC uses the serial cable, not Bluetooth, so it never competes.

Console shows "Patient: not assigned" and a default pressure

No patient is checked out — the board forgets on every power‑cycle (the record lives in RAM only). In the web app, select your patient (or create one). The console updates within a second and START becomes available.

adb devices says unauthorized

On the phone, tap Allow on the "Allow USB debugging?" pop‑up (tick "always allow from this computer"). No pop‑up? Toggle Developer options → USB debugging off then on, keep the phone unlocked, re‑plug USB, and re‑run adb devices until it says device.

npm run android fails: "device not found" / a device‑name error

Have one phone plugged in and run npm run android (no --device flag). If it still fails: adb kill-server; adb start-server; adb devices and make sure exactly one shows device.

npm run android fails: "SDK location not found" / JAVA_HOME / Gradle

The Android toolchain isn't set up. Install Android Studio (SDK + platform‑tools) and JDK 17, open a fresh terminal so the env vars load, and retry — or use the APK shortcut below.

I don't want to install Android Studio / JDK just to test

Ask for a pre‑built APK: someone with the toolchain builds it once and sends you app-release.apk. Copy it to the phone and tap to install (enable "install from unknown sources" once). A release APK runs standalone — no PC, no Metro. (A debug APK still needs Metro running on a PC on the same Wi‑Fi.)

The phone app shows a full red error screen after it was working

The Metro terminal was closed or crashed. Restart it: cd FOLLI_CONSOLE; npm start, then reload the app (shake the phone → Reload, or press r in Metro).

Balloons stay inflated after STOP

Give it up to ~15 s — the vent is pulsed and a stiff balloon drains slowly. If they stay hard after that, press STOP again; if it persists, cut the pump power switch and tell us (that would be a real fault).

Runtime clock or targets read 0 during a phone‑started session

That was a bug we fixed — make sure you pulled the latest main. After pulling, restart the backend (Ctrl‑C, re‑run uvicorn) and reload the web page.

I changed some code — how do I pick it up?

Backend: Ctrl‑C and re‑run uvicorn. Frontend: it hot‑reloads (refresh if odd). Console: hot‑reloads via Metro; for native/asset changes re‑run npm run android.

Everything is weird — how do I reset the app data?

Stop the backend, delete POUCH_APP\backend\folli.db (and the -shm/-wal files if present), restart the backend. You get a clean database (re‑seeds the Mock Pouch; re‑add your device and patient).

A Appendix · reflashing firmware (only if asked)

The board already runs the latest firmware. If you ever need to reflash (with the ESP32 core and NimBLE-Arduino installed):

PowerShell
> cd FOLLI_POUCH\POUCH_ESP_GEN4
> arduino-cli compile --fqbn esp32:esp32:esp32 .
# close the backend first (release the COM port), then:
> arduino-cli upload -p COMx --fqbn esp32:esp32:esp32 .

Serial monitor baud is 9600. After flashing the board comes up unassigned — assign a patient from the web app.

B Appendix · fast restart

Once everything is installed, a normal session is just:

  1. Plug in the ESP (USB); bench power + pump switch on; balloons on TEMPLE/EAR.
  2. Terminal 1: cd POUCH_APP\backend; .\.venv\Scripts\Activate.ps1; python -m uvicorn app.main:app --port 8000
  3. Terminal 2: cd POUCH_APP\frontend; npm run dev → open :5173 → ENTER your pouch.
  4. Plug in the phone. Terminal 3: cd FOLLI_CONSOLE; npm start → press a (or open the installed app and keep Metro running).
  5. Select your patient → run Tests A / B / C.

Something doesn't match what you see? Note the exact screen or message and send it over — most issues are one of the FAQ items above. This guide also lives in the repo as TESTING_RUNBOOK.md on main.
